# `data/concepts/backlog/` — the wiki term-backlog

The **undefined-term backlog** for the wiki glossary: domain terms the platform's prose leans on
that [`data/concepts/`](../) doesn't yet define. It drives **A2** (batch-author concepts, #1566)
in the wiki epic ([#1560](../../../README.md)), workstream A1 ([#1565](../../../README.md)).

One `<scope>.yaml` per scope with any hits:

- a **site slug** (`springfield.yaml`, `fort-wayne.yaml`, …) — harvested from that site's own
  extracted `.md` record (its [`effective_corpus_scope`](../../../src/watermark/sites/__init__.py));
- **`network.yaml`** — the shared `docs/` + `.claude/skills/` prose that belongs to no one site.

A site with no investigative prose gets no file (the tree stays signal-only).

## Each file has two buckets

- **`terms`** — curated-lexicon hits (from [`../lexicon.yaml`](../lexicon.yaml)) not yet in
  `data/concepts/`. This is the actionable backlog: author these as concepts. Each carries a
  `count`, per-file `sources`, an `example` snippet, and an authoring `note`.
- **`candidates`** — mechanically discovered acronyms/initialisms, ranked by frequency and capped
  (`candidates_found` reports the pre-cap total). These need human triage: promote the real domain
  terms into `lexicon.yaml`'s `terms`, and drop the noise into its `stopwords`.

A term drops out of every backlog the moment its concept lands under `data/concepts/` — the
harvest matches candidates against every concept slug, title, and alias.

## Regenerate

```sh
watermark term-backlog            # all sites + network → data/concepts/backlog/
watermark term-backlog --site springfield --no-network --no-write   # preview one scope
```

Generated by [`watermark.site.term_backlog`](../../../src/watermark/site/term_backlog.py); do not
hand-edit these files. Curate [`../lexicon.yaml`](../lexicon.yaml) and re-run instead.
